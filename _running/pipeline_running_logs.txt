STEP 1 — build_bugs_dataset.py
    Output: data/bugs_cleaned.csv
    Key Points of the Script:

        Unifies both severity & priority label normalization (severity_norm, priority_norm)

        Drops only rows with missing both labels, not only one label

        Adds full analytics features (desc_lines, duplicate_ratio, etc.)

        Keeps chunking for memory safety

        Writes final canonical dataset: data/bugs_cleaned.csv

        Compatible with both tasks downstream

        Trainer/prep will pick LABEL_KIND=severity or priority to filter rows

STEP 2 — embedding job (parallel, shards)
    Output: data/embeddings/shards/*.parquet

STEP 3 — topic job + cleanup
    Output: data/topics/topics.parquet
            artifacts/topics/*  (model, centroids, etc.)

STEP 4 — merge_enrichment.py (NEW)
    Output: data/bugs_enriched.parquet
            (cleaned + embeddings + topics)

STEP 5 — prep_from_parquets.py
    - load enriched parquet
    - split train/val/test
    - PCA / scaling
    - fusion
    Output: artifacts/prep/<id>/...

STEP 6 — training scripts (XGB, MLP)
    - severity-aware metrics
    - SHAP / IG / PermIM
    Output: artifacts/models/...

STEP 7 — reporting.py, compare_reports.py
    - use severity metrics
    Output: results/*.json

STEP 8 — run_analytics.py (NEW)
    - uses bugs_enriched.parquet
    Output: analytics/*





What is inside bugs_enriched.parquet?

bugs_enriched.parquet is the full, enriched, unified dataset after: dataset building -> embedding -> topic modeling -> enrichment merging

This file contains everything required for: training, analytics, feature engineering

Below is structure of fields inside bugs_enriched.parquet.

📌 Core Fields (Raw Bugzilla Data)
Column	Description
id	Bug ID
summary	Bug summary text
description	Bug description text
product	Bugzilla product
component	Bugzilla component
platform	Platform
op_sys	Operating system
priority_raw	Raw Bugzilla priority string
severity_raw	Raw Bugzilla severity string
creation_time	Timestamp
last_change_time	Timestamp
other raw Bugzilla fields	depends on your dataset
📌 Engineered Feature Columns

Text statistics: summary_len, desc_len, desc_lines, desc_words, desc_unique_words, desc_paragraphs

Crash / structural indicators: has_stacktrace, has_crash_sig, crash_sig_len, crash_kw_score, severity_kw_score

Graph / dependency counts: duplicates_count, duplicate_ratio, depends_on_count, blocks_count, regressions_count, regressed_by_count, cc_count, attachments_count, comment_count, votes

📌 Label Columns

Two parallel label spaces:

Severity labels

severity_raw

severity_norm → canonical S1/S2/S3/S4

Priority labels

priority_raw

priority_norm → canonical P1/P2/P3/P4/P5

📌 Embedding Column
embedding      → numpy array, ~384-dim from MiniLM
Stored as: object dtype, each row = np.ndarray
This is fed into PCA during prep.

📌 Topic Columns
From topic_jobs + cleanup:
topic_A_clean, topic_B_clean

📌 Why changed to this layout

Because it lets the pipeline:
- generate clean features once
- run embedding once
- run topics once
- run ML prep separately for severity/priority
- run analytics on unified fields
- avoid duplicated storage
- preserve all possible stats for both tasks

This is the ideal structure for a large-scale ML/SE pipeline.



prep_from_parquets (prepare features for training) PIPELINE:
Work based on input data/bugs_enriched.parquet 
        │
        ├── Filter rows (strict): embedding + topic_B_clean + label available
        │
        ├── Time-based split (TRAIN/VAL/TEST from .env)
        │
        ├── Load centroids + topic_map (Option 2 structure)
        │
        ├── Build topic embedding PCA
        │
        ├── Build text embedding PCA (MiniLM)
        │
        ├── Build Top-K similarity features
        │
        ├── Build numeric block
        │
        ├── Build categorical PCA-embedded block (Option B)
        │
        ├── Build actors hash block
        │
        ├── Apply fusion scheme (A1–A4, B1–B2)
        │
        ├── StandardScaler (train-fit, val/test-transform)
        │
        ├── Save feature matrices to artifacts/prep/<prep_id>
        │       X_train.arrow
        │       X_val.arrow
        │       X_test.arrow
        │       y_train.npy
        │       y_val.npy
        │       y_test.npy
        │
        └── (Optional) export analytics/full_features.parquet

Output of prep step:
artifacts/prep/<prep_id>/
    topic_centroids.clean.npy
    topics_map.clean.json
    ...
